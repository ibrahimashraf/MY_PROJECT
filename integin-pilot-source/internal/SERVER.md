# INTEGIN HTTP Server Composition

`internal/server` mounts the authoritative sync adapter at `POST /sync`, tenant-scoped evidence upload at `POST /evidence` when an object store is injected, a liveness route at `GET /healthz`, and a dependency-aware readiness route at `GET /readyz`. Every request receives or preserves an `X-Correlation-ID`, request bodies are bounded to 10 MiB, access logs are emitted as structured records, and the runnable server sets read, write, idle, and header timeouts.

When `INTEGIN_DB_URL` is configured, startup opens PostgreSQL through the open-source `lib/pq` driver, verifies connectivity, loads all tenants listed in `INTEGIN_TENANT_ID` or comma-separated `INTEGIN_TENANT_IDS`, hydrates devices and active authority packages from the durable repository, and gives the sync processor the durable receipt/sequence/held-transaction repository. JSON files remain an explicit local-development fallback only when `INTEGIN_DB_URL` is absent. The fallback must not be used as a production trust registry.

Evidence storage is disabled by default. `INTEGIN_EVIDENCE_STORE=memory` enables the local test adapter. The approved production setting is `INTEGIN_EVIDENCE_STORE=rustfs`, which requires the generic S3 variables `INTEGIN_S3_ENDPOINT`, `INTEGIN_S3_BUCKET`, `INTEGIN_S3_ACCESS_KEY`, and `INTEGIN_S3_SECRET_KEY`; `INTEGIN_S3_REGION` defaults to `us-east-1`. RustFS's S3 API is accessed through the vendor-neutral `storage.S3Store` adapter and the built-in dependency-free AWS Signature Version 4 signer. The legacy `minio` mode and `INTEGIN_MINIO_*` variables remain accepted for migration compatibility. The server uses a 15-second graceful-shutdown window and closes the database connection after HTTP shutdown.

The field app’s HTTP transport can target the configured server endpoint. End-to-end deployment still requires a real authority registry, TLS/reverse-proxy policy, and a local integration harness that exercises Applied, Duplicate, Held, Rejected, Conflict, and Security Failure outcomes.

For RustFS, run a pinned image or binary rather than `latest`, expose the S3 API only to the INTEGIN server network, and keep the RustFS console on an administrator-only network. The RustFS container runs as a non-root service account; bind-mounted data and log directories must be writable by that account. Configure TLS or place RustFS behind a trusted TLS reverse proxy, create a dedicated evidence bucket, use a dedicated access key with only the required bucket permissions, and maintain an independent backup of encrypted object bytes plus the PostgreSQL evidence manifest. A minimal development deployment can use the official `rustfs/rustfs:<pinned-version>` container with ports `9000` for S3 and `9001` for the console; production deployment must add durable volumes, credentials, network controls, monitoring, and restore verification.
